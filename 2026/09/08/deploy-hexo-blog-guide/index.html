手把手把博客部署到 GitHub Pages

Hexo 教程 GitHub Pages
技术
发布日期:   2026-09-08

博客在本地跑起来只能自己看到，要让全世界访问，还需要把它”推”到 GitHub Pages。
这一篇专门讲清楚”部署到线上”的完整流程：怎么建仓库、怎么打通本地到 GitHub 的连接、怎么改配置、怎么发布、重载网页怎么办、自己写一键部署脚本，以及一路上可能踩到的坑。

部署之前，请确保你已经在本地跑过一个能正常显示的 Hexo 博客（参考上一篇《从零到上线：手把手部署一个 Hexo 博客》）。现在我们要把它推到公网。

一、在 GitHub 上建一个仓库

GitHub Pages 要求每个账号只能用一个同名仓库托管一个静态站点。所以仓库名必须是：

比如你的用户名是 LHT-one-time，那就建 LHT-one-time.github.io。名字差一个字母都不行，也别勾选 Private（GitHub Pages 免费版只支持 Public）。

操作 说明
1. 登录 GitHub → 右上角 + → New repository 打开创建表单
2. Owner 选自己的账号，Repository name 填 你的用户名.github.io 名称必须严格匹配，GitHub 会给出绿色对勾表示可用
3. Public（蓝色选中框） GitHub Pages 免费版只支持 Public，Private 无法访问
4. 不要勾 “Add a README” 它会加一个 README.md，与 Hexo 模板冲突
5. 点 Create repository 进入新仓库页面（暂时空着，后面把博客推上来）

创建完成先放着别动。下一步：让本机能”登入”GitHub。

二、本地连接 GitHub：两种方式

要让本机的 git 能往 GitHub 推代码，需要认证。两种方式都可以：

方式 优点 缺点
HTTPS + Token 配置简单，GitHub 官方推荐 每次换机器都要重新登录
SSH Key 一台电脑一次配好长期生效 初次配置稍麻烦，需要到 GitHub 网页贴公钥

两种方式都能跑通博客部署，挑你顺手的。下面分别讲。

方式 A：HTTPS + Windows 凭据管理器（最省事）

A1. GitHub 生成 Personal Access Token（如果用 GitHub Desktop 或已存过密码可跳过）

  1. GitHub 右上角头像 → Settings
  2. 最下面 Developer settings
  3. Personal access tokens → Tokens (classic) → Generate new token
  4. 名字随便起（如 hexo-deploy），过期时间选 No expiration
  5. **Scopes 勾上 repo**（这够用了）
  6. 生成后复制那个 token 字符串（只显示一次，关掉就没了）

A2. 第一次推送时 Windows 会弹窗

如果你机器上已经用浏览器登录过 GitHub，Windows 会自动把凭据保存到 Credential Manager（凭据管理器）。之后部署时 git 会自动从那里取凭据，不用再手动输入。

查看凭据管理器：控制面板 → 用户账户 → 凭据管理器 → Windows 凭据，搜 github.com 可以看到已保存的项。

如果想更省心，可以配 SSH key——一台电脑配一次，以后再部署都不用输入任何东西。

完整字段说明：

字段 怎么填 说明
type: git 固定 用 git 方式推送
repo: 你的仓库 URL HTTPS 填 https://github.com/用户名/用户名.github.io.git，SSH 填 git@github.com:用户名/用户名.github.io.git
branch: main 通常是 main 2020 年后新建的 GitHub 仓库默认是 main，老仓库可能是 master
message: 'Site updated: {{ now("YYYY-MM-DD HH:mm:ss") }}' 可选，每次部署的提交说明，不填也行

六、重新部署 = 重载网页

重新部署 ≠ 刷新本地缓存，而是把更新后的内容推到 GitHub。流程：

  1. 改了 source/_posts/ 下任何 .md 文件
  2. 改了 _config.yml
  3. 加了新主题、改了图片
  4. → 跑 hexo g && hexo d（或双击 deploy.bat）
  5. → 等 1-2 分钟
  6. → 访问 https://你的用户名.github.io 看新内容

怎么知道网页到底有没有更新？

GitHub Pages 有缓存，且浏览器也会缓存。判断有没有真正生效的方法：

操作 用途
**Ctrl + F5**（Windows） / ⌘ + Shift + R（Mac） 强制刷新，绕过浏览器缓存
等 1-2 分钟 GitHub Pages 服务端构建需要时间，刚部署完立刻看不一定更新
按 F12 → Network → 勾 “Disable cache” → 刷新 开发者工具里关闭缓存

还有个笨办法：访问线上网站时按 Ctrl + F5 一次，如果看到最新内容，就是部署成功。如果还是旧内容，要么部署没成功，要么还在构建中。

坑 3：找不到远程分支 / branch 填错

现象：推送时报 error: failed to push some refs 或者推到了一个诡异的分支。

解决：

  • 看 GitHub 上你仓库的默认分支是什么（Settings → Default branch）
  • 把 _config.yml 的 deploy.branch 改成那个分支（通常是 main，老仓库可能是 master）

坑 4：本地改了，线上不变

两种可能：

  1. 没部署：你只改了 source/ 里的文件，没运行 hexo d 或 deploy.bat。线上当然不变。
  2. 部署了但浏览器缓存：按 Ctrl + F5 强制刷新一次。

坑 5：首页文章卡片图不是我设置的封面

这是 Matery 主题的”特点”——它读 front-matter 里的 img 字段，不读 cover。如果你只设了 cover: /images/xx.png，会不生效。

坑 6：仓库名写错，或者忘记改 _config.yml 里的用户名

现象：本地预览正常，一部署就 404，或者推到别人仓库里去了。

解决：去 GitHub 确认仓库 URL 是 https://github.com/你的用户名/你的用户名.github.io.git，跟 _config.yml 里 deploy.repo 完全一致。

坑 7：deploy.bat 推送卡住一直等

如果你机器上没存过 GitHub 凭据，git push 会等你在控制台输入用户名和密码。deploy.bat 是非交互的，会一直卡着。

解决：在控制面板 → 凭据管理器 → Windows 凭据 里添加 github.com 的凭据（用户名 + token），或者改用 SSH。
